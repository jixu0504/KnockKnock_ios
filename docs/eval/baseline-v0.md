## 调参过程中修正的两个真实缺陷

1. **双通道地板过低（lexical 1.0 / vector 0.10）**：像「最近」这类通用时间词在 N≈27 的语料里
   BM25 约 1.5–1.7，配合哈希向量的偶然重合会把背景记忆带进注入（holdout 出现 6 条背景注入）。
   收紧为 lexical ≥1.5、vector ≥0.15，并要求**命中 ≥2 个查询词**。
2. **只看总分、不看词的区分度**：通用词叠加也能凑过阈值。新增「判别性词」门槛：
   词法准入必须至少命中一个 `IDF ≥ 1.5` 的词；否则即使总分达标也不注入。
   修复后 tune precision 从 0.78 → 0.83，holdout precision 0.50 → 0.69，abstention 保持 100%。
3. **同事实多版本重复注入（X-03）**：为向量候选补上 `originMemoryId`，选中后按 fact/topic key 去重，
   同组只保留层级最高的一条（L3>L2>L1）。回放集新增 g9（L1+L2 同一事实），重复注入用例为 0。
4. **相反极性同轮注入（T78 前置保护）**：新增事实键基座比较，选中后若同一事实出现相反极性，
   只注入较新的一条（旧条目不删除、不归档，供 T78 关系/双时间审计）。回放集 g10 验证「矛盾注入用例 = 0」。
5. **双通道合并丢统计**：同一记忆同时被两通道命中时，合并只保留了 `lexicalScore`，
   丢了「命中词数/最高 IDF」，导致词法候选被误判为非判别性（tune hit 一度跌到 5/14）。
   合并时三个字段一起保留。

## 仍然失败的用例（保留集，语义类）

| 用例 | 查询 | 期望记忆 | 失败原因 |
|---|---|---|---|
| g2c2（tune） | 我多大了 | 用户今年三十岁 | 字面不重合（“多大” vs “三十岁”），需要语义/实体链接 |
| g4c3（tune） | 周末有什么安排 | 周六用户临时加班，电影改到周日 | “周末”与“周六/周日”不共享 n-gram |
| g5c3 | 我喝什么饮料 | 用户偶尔喝无糖可乐 | “饮料”与“可乐”无字面重合 |
| g7c3 | 我能养猫吗 | 用户喜欢猫但房东不让养 | 否定/意图改写（“养猫” vs “不让养”） |
| g8c4 | 我会什么乐器 | 用户在学吉他 | 概念级关联（乐器→吉他） |

**结论**：这 5 类正是「哈希向量不具备语义能力」的边界（计划书 R1）。在 G1 指标不达标时，
应按计划启动 T92（Core ML PoC）或允许用户配置第三方嵌入；词法阈值的进一步放宽不会解决它们，
只会换来噪声。
