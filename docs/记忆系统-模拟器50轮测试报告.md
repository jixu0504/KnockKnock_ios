## 二、关键 Bug（测试中发现并已修复）

### 1. 记忆抽取 401：Key 在 Keychain，管线却读 settings 明文（严重）

- 现象：58 轮聊天正常，但 `memory_source_queue` 4 个窗口全部 401：`No API-key provided`。
- 根因：`MemoryV2Pipeline.requestMemoryModel` 使用 `settings.apiKey`；iOS 保存供应商后明文被清空，真实 Key 在 Keychain。
- 修复：新增 `apiKeyProvider` 注入；`PrivatePromptWiring` / `A7MemoryWiring` 用 `ProviderConfigResolver.apiKeyFor(...)` 从 Keychain 取 Key。
- 验证：同一批队列重试后 4/4 成功，生成 18 条记忆。

### 2. RRF 平票被纯向量候选压过（影响召回）

- 现象：Q2 实体通道命中 1 条「团子」，但注入预算被咖啡/住址挤掉。
- 根因：实体/词法单通道与纯向量候选 fused 相同（都是 1/61），按私有分排序时实体输给泛化向量。
- 修复：fused 加 `lexicalScore * 0.0001` 平票打破，让词法/实体强命中优先。
- 效果：Q2 开始出现团子相关信息（但仍未正确回答年龄），其余查询未改善。

### 3. 详情页残留内部字段（已修）

- 去掉「等级别名 SHORT_TERM」「会话 session_e2e_…」「来源引用 …epoch0:12-23」，类型显示中文。

## 三、失败分析

### 3.1 召回为什么只对 1 题？

以 25 条 L1、20 个候选为例，每轮只注入 2–4 条。日志（`Library/Application Support/logs/rhodes.log`）显示：

- Q1 咖啡：候选 19 → 准入 4 → 注入 2，命中；
- Q2 团子：实体 1 + 词法 17 → 准入 4 → 注入 2，团子被挤掉（修复后进入但回答仍不稳定）；
- Q3 忌口：词法 12 → 准入 4 → 注入 4，香菜未进入前 4；
- Q4 住址：注入 3，但杭州/浦东两条互相冲突；
- Q5 承诺：注入 3，电影承诺未进前 3；
- Q6 天气：注入 2，下雨记忆未进前 2。

结论：**不是“没有记忆”，而是选择阶段只取前 2–4 条，且排序仍被近期/泛化候选主导**。需要按查询意图提高实体/词法强命中的名额与权重。

### 3.2 印象为什么是 0？

模型把同一事实写成不同键：

```
fact:positive:user|prefer|美式咖啡不加糖
fact:positive:user|prefer|美式咖啡|q=每天一杯
fact:positive:user|prefer|美式咖啡|q=不加糖
```

三句“喜欢美式”没有一条重复的 factKey，晋升分组要求同键 ≥3 条，因此 L2 无法形成，L3/印象自然为 0。**这是抽取层客体/限定词归一化缺口**，不是印象表本身的问题。

### 3.3 页面为什么看起来有印象？

`ImpressionsBridge` 在 `impressions` 表为空时回退旧 `memory_items` 过滤视图，把 L1 标成“互动印象”。这会让测试者误以为印象系统工作。建议回退时明确标注“旧视图”，或空表时显示空态。

### 3.4 查询本身生成记忆

查询会话产生 4 条元记忆（如“用户连续询问咖啡、团子…”），说明抽取对“提问句”缺少跳过规则，会增加噪声。建议对纯提问、核对类消息降低抽取权重或不生成长期事实。

## 五、建议的下一步（按优先级）

1. **事实归一化**：客体去限定词（“不加糖/每天一杯/三岁”），限定词进 qualifiers；同 (subject,predicate,object) 归并，才能形成 L2。
2. **召回选择重排**：按意图给实体/词法强命中保留名额；不要先按“最近 L1”固定取 2 条。
3. **查询句过滤**：纯提问/核对消息不生成长期事实。
4. **空表不伪装**：印象页回退旧视图时明确标注，避免验收误判。
5. **状态变更**：T78 supersedes/valid_to 落地后，杭州→上海应关闭旧事实。

### 7.2 根因与修复清单

| 问题 | 根因 | 修复 |
|---|---|---|
| 抽取全部 401 | 记忆管线读取已清空的 `settings.apiKey`，真实 Key 在 Keychain | `MemoryV2Pipeline` 增加 `apiKeyProvider`；iOS 两处装配通过 `ProviderConfigResolver` 从 Keychain 取 Key |
| 同一事实多个键，L2/L3 不形成 | 客体/qualifier 写法漂移 | `MemoryParseRules` 新增客体头部归一与 `groupKeyOf`；晋升按归并键分组；同事实去重按“极性 + 归并基座” |
| 小语料召回为 0 | 绝对 BM25 阈值高于小语料 IDF 上限，且泛化候选挤占名额 | 新增确定性「查询—事实」证据：客体别名/正文直接命中、谓词问法命中（住→reside、不吃/讨厌→dislike），并让强命中先占注入名额 |
| 新逻辑误放行一般问题 | 初版证据匹配与统一降阈过宽 | 收窄为“关于我/我的记忆”或“某实体叫什么/几岁/是谁”；撤回统一降阈，保留原 abstention 门槛 |
| 查询生成元记忆 | 提问窗口也进入抽取 | `MemoryIngestFilter` 对纯提问窗口整体跳过，陈述句仍正常抽取 |
| 住址旧值仍被当现状 | 单值事实换值未关闭，且初版取代方向会误伤新事实 | 单值谓词（住址/工作/生日等）只允许旧→新 `supersedes`；关闭 `validTo`、归档旧记忆，并在召回前剔除被取代项 |
| 印象页看起来像已形成 | 新表为空时静默回退旧视图 | 回退时明确显示「长期印象还在形成中：这里暂时展示的是已记录的记忆条目」 |
