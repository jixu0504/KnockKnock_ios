## 一、执行结论

项目技术上可行；执行路径为 **路线 A 的裁剪版：KMP 共享核心 + SwiftUI 原生 iOS 客户端**，全部工程工作由 DSH 代理完成。

与原计划书相比，v1.1 的关键变化：

1. 范围进一步收紧：聊天记录导入降为条件项、心情不做手动编辑、每日自动内容只保留两项（有整体移植的触发条件）。
2. 排期与成本不再按「人类程序员 × 人月」计算，改为「代理日 × 并行度 × 墙钟」模型（详见第七章），基准 **6-7 个月**，现金成本基准 **约 ¥3.5-6 万**（不含用户本人时间与既有 Mac）。
3. 工程纪律因无人类兜底而**上移为第一优先级**：所有模块必须「规格卡先行 + Android 1.14.27 作为 oracle + 金样 diff 测试 + 阶段 Gate」，杜绝代理自由发挥。

## 二、需求规格

### 1. 产品目标（不变）

在数据模型、提示词、记忆召回、会话状态、备份恢复和用户可见行为上与 Android 1.14.27 保持一致，范围如下（A 类）。「原版全部功能」= 逐项可勾选的 Android 对照清单，含每个页面、入口、按钮、状态、错误提示、空状态、权限分支和数据变化。

### 2. 范围分级

#### A1. 核心聊天（修订）

- 私聊会话；
- 三种互动模式（线上 / 线下 / 导演）；
- **心情系统（修订：仅移植原版）**：AI 输出的【状态/心情/位置】标签的解析、聊天头部状态菜单的展示、`OperatorStateUpdater` 逐轮更新、注入提示词对聊天行为的影响。**不新增手动编辑入口**；
- 流式回复、超时、取消、失败和重试；
- 消息引用、撤回、重试，以及原版已有的其他消息操作；
- 剧情存档、聊天历史、重新开始和历史会话恢复；
- 群聊、群成员、成员权限、群聊人设；
- 群聊自动互动（原版规则），改用 iOS 可实现的「前台补算 + 本地通知」语义。

#### A2. 角色、关系与资料（不变）

角色创建/编辑/人设、角色卡导入导出、头像裁剪与相册导入、20+ 关系类型及关系网展示/编辑/删除、用户身份/印象/等级的全部原版功能。

#### A3. 记忆与知识库（不变）

三层记忆、锚点、生成、维护、编辑、删除、隐私；向量嵌入/召回/签名隔离/会话隔离；知识库导入/切块/索引/召回/管理；提示词注入顺序、限额、优先级、异常处理；空库、索引失败、供应商不可用、迁移后行为。以「行为不变、数据不丢失」为验收标准。

#### A4. 内容生态（不变）

动态广场（发布/查看/点赞/评论/删除/刷新/空态/错误态/生成逻辑）、干员日记、聊天排行榜与消费统计、大家的印象。

#### A5. 数据、备份与迁移（修订）

- 完整备份/恢复、分类备份、分页数据、媒体、角色、会话、消息、记忆、知识库、动态、设置的迁移；
- **Android 1.14.27 完整备份可在 iOS 导入并正确恢复（100% 金样通过）**；
- 备份格式版本号、校验、明确错误提示；密钥不进备份；恢复失败可回滚；恢复后自检；
- **聊天记录导入（修订：条件项）**：
  - 格式约定（若做）：`RhodesLinkChatExport.zip` = `manifest.json` + `conversation.json` + `media/`（相对 mediaId）；
  - **决策规则**：Phase 2 前完成 ≤3 代理日的可行性验证（含 Android 侧是否需新增导出器）；预计总投入 ≤8 代理日则纳入一期；否则移二期候选，一期不做；
  - 若做，Android 侧导出器先行，iOS 只导入 Android 能生成的格式。

#### A6. 设置、调试与客服范围（不变）

11 个模型供应商配置、自定义端点、连接测试/流式/超时/取消/错误提示、聊天表现设置、完整提示词编辑器（查看/编辑/保存/恢复默认/启用禁用/变量替换/实际生效）、外观设置首版仅「跟随系统」、调试日志查看/导出、权限管理、通知与文件分享按可用性移植。

#### A7. 自动化互动（新增，按补充 3 裁决）

- **保留**：动态定时回复（`MomentReplyWorker` 等价物）、记忆维护（`ContextMaintenanceWorker` 等价物）、群聊自动互动（在 A1）；
- **默认不移植**：每日动态、主动私聊、免打扰时段、手动回复定时器；
- **整体移植触发条件**：Phase 1 中段由领域代理评估——若拆分上述两项所需改动的调度/提示词管线 ≥ 完整移植工作量的 80%，则改为整体移植（上述 4 项一并纳入 A7）；
- **预算口径**：默认按「整体移植」编制排期（+6-10 代理日缓冲），若最终确认只做两项，相应提前。

#### 排除范围（修订）

- 麻将、斗地主、跑得快；Galgame；语音输入/ASR/TTS/语音通话/陪睡；客服求助；开屏动画与音效（均明确排除首版）；
- 报纸、派遣、礼物：二期候选；
- **每日动态、主动私聊、免打扰、手动回复定时器：二期候选（若触发 A7 整体移植条件则随 A7 纳入）**。

### 3. 必须新增的 iOS 前置要求（自签场景修订，见七.6：年龄/举报/隐私/审核类合规项全部移除，仅保留 Keychain、局域网权限说明、通知时机、辅助功能与后台语义）

年龄确认与内容强度设置、举报/屏蔽与内容边界说明、隐私政策与数据处理说明、审核账号/审核说明、Keychain 存密钥、局域网端点权限与错误提示、通知权限时机、降低透明度/增强对比度/减少动态效果、后台行为说明（前台补算 + 本地通知，不承诺准点）。

### 4. 统一验收标准（不变，补充自动化）

- 功能一致性：A 类逐项通过 Android 1.14.27 对照清单；同一角色/设置/输入两端提示词相同（允许平台字段差异）；Android 备份在 iOS 恢复后可用；
- 数据正确性：23 个迁移在 iOS 可执行；绝对路径全部媒体 ID 化；导入失败可定位可回滚；密钥不进备份；
- 性能：2,000 条消息时间线流畅；10,000 条记忆召回真机压测并有优化；流式首 token/取消/超时/半包/网络切换有测试；冷启动/迁移/恢复/媒体导入有耗时记录；无阻断性崩溃；
- 兼容性：iPhone 小屏/大屏、深色/浅色、动态字体、降低透明度通过；iOS 18+ 基线、iOS 26+ 增强玻璃；真机验证网络/照片/相机（如后续保留）/通知/局域网端点/文件导入导出/系统中断；
- **补充（DSH 执行前提）**：每项验收必须有**可自动判定的产物**（测试报告、金样 diff、截图基线、性能数据），否则该项视为未定义。

## 三、技术架构计划

### 1. 目标分层（不变）

```text
shared/commonMain
├── domain                # 聊天、群聊、心情、关系、身份、等级、自动化调度
├── prompt                # 提示词模板、变量、编辑器模型、版本
├── memory                # 记忆、向量、知识库、召回、注入、维护
├── data                  # SQLDelight 仓库、迁移、导入导出模型
├── network               # 11 个供应商、自定义端点、SSE、错误与重试
├── backup                # 备份、恢复、版本、校验、回滚编排
└── commonTest            # 双端共用行为契约测试 + 金样

shared/androidMain        # Android 驱动、路径、通知、WorkManager 适配
shared/iosMain            # iOS 驱动、Keychain、文件、路径、BGTask 适配

iosApp
├── SwiftUI App Shell     # Tab、NavigationStack、系统外观、深链
├── DesignSystem          # Glass/Material token、颜色、间距、可访问性
├── Features              # 聊天、资料、记忆、内容、设置等页面
└── Bridges               # KMP 门面 → Swift AsyncStream/struct
```

### 2. 关键架构原则（不变）

不在 Swift 重写提示词/记忆/状态机/备份规则；`IosAppGraph` 窄门面 + Swift struct；Flow→回调/AsyncStream；Keychain 存密钥、JSON 文件存配置；媒体只存相对 ID；玻璃只用于导航/输入栏/浮动操作/设置卡片；双端共用黄金样本。

### 3. DSH 协作层（新增）

```text
lead（根代理：范围裁决、Gate 验收、合并决策、对外汇报）
├── p0-toolchain（工具链与环境）
├── domain-chat / domain-group（私聊/群聊引擎）
├── domain-prompt-memory（提示词 + 记忆 + 知识库）
├── domain-backup-data（备份/迁移/媒体 ID 化）
├── ios-infra（DB/网络/设置/门面/系统服务）
├── ios-shell-design（导航/玻璃设计系统/可访问性）
├── ui-wave-*（按功能波次拆分的页面代理）
├── reviewer（每阶段 diff 审查 + 回归判定）
└── qa（对照清单执行、模拟器/真机验证、金样比对）
```

协作规则：

1. **写域隔离**：每个代理只写任务板上声明的目录；跨域只通过 `shared/domain` 接口；合并前由 reviewer 审 diff。
2. **规格卡先行**：每个模块先产出规格卡（输入/输出/边界/验收/对应 Android 源码位置），reviewer 批准后才写实现。
3. **oracle 优先**：Android 1.14.27 是行为 oracle；金样（提示词、备份包、会话）在 Phase 0 冻结并入库。
4. **上下文 checkpoint**：每个阶段结束产出 `handoff.md`（已完成/未完成/决策记录/已知问题），后续代理以 fork + handoff 续接，避免单会话上下文无限膨胀。
5. **构建串行化**：单机构建是共享资源，排期按「编写并行、构建串行」处理；夜间批量跑回归。
6. **人类签字点**（非编程）：玻璃视觉观感、产品范围裁决、App Store 账号/证书/TestFlight、合规材料与审核回复。其余全部由代理闭环。

## 四、分阶段开发计划（DSH 执行版）

> 各阶段给出：目标、交付物、Gate、代理投入（agent-day，1 agent-day ≈ 1 个代理 1 个工作日全量工作）、并行度、墙钟。agent-day 定义与换算见第七章。

### Phase 0：环境与范围冻结（墙钟 2 周）

- 代理任务：安装 JDK 21、Android SDK 35、Kotlin/Native、iOS 模拟器 runtime；升级 Kotlin 2.3.x / Gradle / Xcode 工具链，验证 Android 构建不回归；加 iOS target，跑通 SQLDelight native driver + Ktor Darwin + shared framework；用真实供应商验证流式（首 token/取消/超时/自定义端点）；Android 完整备份 → iOS 恢复最小闭环；2,000 条消息时间线原型；后台任务 + 本地通知实验；SwiftUI 玻璃壳 Demo；冻结 1.14.27 基线（APK、数据库、备份、媒体、金样）。
- 投入：约 10-14 agent-day；并行度 3-4。
- **Gate 0**：双端可构建；数据库打开并完成迁移；真实流式请求可返回可取消；Android 备份可恢复到 iOS；2,000 条消息滚动达标；最低 iOS 版本（建议 18+）与玻璃验收标准冻结。

### Phase 1：共享领域层抽取（墙钟 4-5 周，关键路径）

- 交付物：私聊/群聊轮次与状态机、三种模式、心情（仅移植）、引用/撤回/重试、角色/关系/身份/印象/等级领域服务、提示词模板/变量/版本、记忆生成/维护/召回/注入、知识库导入/切块/索引/召回、备份/恢复模型 + 媒体 ID 化 + 自检、A7 自动化决策（拆分 vs 整体移植）与实现、第一批 commonTest 黄金用例。
- 投入：约 60-75 agent-day；并行度 3-4（按 domain 拆分，写域隔离）。
- **Gate 1**：Android 原功能不回归；核心提示词/记忆测试全绿；共享层不依赖 Android Context/WorkManager/UI；A7 决策点完成（输出拆分/整体移植的成本对比与结论）。

### Phase 2：iOS 基础设施和数据底座（墙钟 2.5-3 周）

- 交付物：SQLDelight iOS driver + 23 迁移、`IosAppGraph` 与桥接层、Ktor Darwin/SSE/取消/重试、Keychain + 配置 JSON 原子写、`MediaStore` 相对 ID 与清理、完整备份/恢复/导入导出、角色卡导入导出、文件选择/分享/剪贴板/通知/深链/日志导出；聊天记录导入可行性验证（≤3 agent-day，输出「做/不做」结论）。
- 投入：约 30-38 agent-day；并行度 3-4。
- **Gate 2**：Android 备份在 iOS 恢复后自检通过；导入失败不污染数据库；密钥不进备份；聊天记录导入裁决完成。

### Phase 3：iOS 壳、设计系统和聊天原型（墙钟 2.5-3 周，可与 Phase 2 尾并行）

- 交付物：TabView/NavigationStack/路由/深链、跟随系统外观、Glass/Material token、环境背景、输入栏、浮动按钮、系统弹窗、辅助功能（降低透明度/增强对比度/减少动态效果/动态字体）、聊天时间线最终方案（必要时 UICollectionView 包装）。
- 投入：约 25-32 agent-day；并行度 2-3。
- **Gate 3**：键盘无跳变；深浅色与辅助功能可读；滚动稳定；玻璃元素不过度堆叠。**（人类签字点：玻璃观感评审）**

### Phase 4：功能波次一——聊天、角色和关系（墙钟 3-4 周）

- 交付物：私聊/三种模式/心情展示、流式/取消/重试/引用/撤回、剧情存档/历史/重开、群聊/成员/权限/人设、角色创建编辑/角色卡、头像裁剪/相册导入、联系人/搜索/20+ 关系/关系网、用户身份/印象/等级。
- 投入：约 45-60 agent-day；并行度 4-5（按页面族拆分）。
- **Gate 4**：对照清单逐项通过；覆盖空数据/网络失败/模型超时/重复发送/切换会话/恢复历史/中断恢复。

### Phase 5：功能波次二——记忆、知识库和设置（墙钟 2-3 周）

- 交付物：记忆/向量/知识库全流程 UI、11 供应商配置/自定义端点、聊天表现、完整提示词编辑器、调试日志/权限/通知/外观设置、A7 保留项（动态定时回复 + 记忆维护，或整体移植）的 iOS 后台语义接入。
- 投入：约 28-36 agent-day；并行度 3-4。
- **Gate 5**：同一输入/设置下两端提示词结构、记忆召回、注入结果金样 diff 对齐；编辑结果可持久化/导入/恢复。

### Phase 6：功能波次三——内容生态（墙钟 2-2.5 周）

- 交付物：动态广场、干员日记、排行榜/消费统计、大家的印象，及通知、生成失败、空态、分页、刷新。
- 投入：约 20-28 agent-day；并行度 3-4。
- **Gate 6**：原版内容操作与状态全部有对应入口；生成失败不破坏已有内容；恢复备份后内容可继续使用。

### Phase 7：合规、性能、兼容性和发布（墙钟 3-4 周代理 + TestFlight/审核 3-5 周日历，可并行）
