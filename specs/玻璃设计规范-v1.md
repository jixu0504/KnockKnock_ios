# 玻璃设计规范 v1（RhodesLink iOS 液态玻璃）

> 依据：`RhodesLink-iOS可行性分析报告.md` §4（API 事实 / 版本策略 / 界面映射 / 代码骨架）+ 附录 C 验收清单。
> 落地验证物：`ios-port/iosApp-demo/GlassShellDemo`（Phase 0 SwiftUI 玻璃壳 Demo，Xcode 27.2 编译通过）。
> 状态：v1，Phase 0 冻结；视觉观感为人类签字点，Phase 3 真机/模拟器复查后升版。

---

## 1. 设计原则（一票否决项）

1. **三层结构**：环境背景（渐变/光斑/立绘模糊）→ 内容层（不透明或高对比）→ 玻璃 chrome（导航、输入栏、浮动操作、设置卡片）。
2. **一屏玻璃元素 ≤ 5 个**；相邻玻璃元素放进同一个 `GlassEffectContainer` 合并（融合折射、无重叠阴影）。
3. **玻璃上不放正文**；玻璃上的文字至少 17pt（.body 起），对比度 ≥ 4.5:1。消息气泡、长文、表格、游戏画面一律不用玻璃。
4. **统一 token**（下表），页面层只引用 token，不写死材质值。
5. **必须响应**：降低透明度、增强对比度、减弱动态效果、粗体文字、Dynamic Type。

## 2. Token 定义（`DesignSystem/GlassTokens.swift`）

| Token | 值 | iOS 26 映射 | iOS 18 兜底映射 | 说明 |
|---|---|---|---|---|
| `glassRegular` | — | `Glass.regular.tint(glassTint)` | `.ultraThinMaterial` | 标准玻璃 |
| `glassClear` | — | `Glass.clear.tint(glassTint)` | `.thinMaterial` | 轻玻璃（头部条等） |
| `glassTint` | `#FF9420` | 玻璃折射色调 | 卡片/图标强调色 | 品牌橙 |
| `glassStroke` | `white @ 18%` | 1px 边缘高光描边（统一叠加） | 同左 | 增强对比度时升为 `glassStrokeStrong`（34%）；粗体文字时线宽 1→1.5pt |
| `glassRadius` | 24pt | 统一圆角 | 同左 | 允许档位 20 / 24 / 28 |
| `glassShadow` | `black @ 25%`，radius 12，y 6 | 玻璃投影 | 同左 | 「降低透明度」模式下禁用 |
| `ambientTop/Bottom` | `#0B1020 → #1A2238` | 环境背景渐变 | 同左 | 深海军蓝，深色为主 |
| `ambientGlowOrange/Blue` | 橙 18% / 蓝 14% | 光斑 | 同左 | 光斑模糊 60–90pt |
| `brandOrange/Deep` | `#FF9420 / #D96A00` | 品牌色、发送按钮 tint | 同左 | 发送气泡渐变 |
| `glassCardSpacing` | **12pt** | 玻璃卡片间距 | 同左 | 玻璃不叠玻璃 |
| `maxGlassPerScreen` | **5** | 设计原则常量 | 同左 | 含系统导航栏/Tab Bar |
| `textOnGlassMinPointSize` | **17pt** | 玻璃上文字下限 | 同左 | `.body`/`.headline` |

材质映射集中在 `GlassPanel`（统一玻璃表面组件）与 `GlassInputBar` 两个组件内做 `if #available(iOS 26.0, *)` 分支；页面层不出现任何 iOS 26 专属 API。

## 3. 一屏玻璃 ≤ 5 原则（本 Demo 各页计数）

| 页面 | 玻璃元素 | 计数 |
|---|---|---|
| 聊天 | 系统导航栏 + 输入栏容器（3 个玻璃元素经 `GlassEffectContainer(spacing:10)` 合并计 1）+ Tab Bar | 3 |
| 角色 | 系统导航栏 + 薄玻璃头部条 + 2 张角色卡 + Tab Bar | 5 |
| 记忆 | 系统导航栏 + 1 张摘要卡 + Tab Bar | 3 |
| 设置 | 系统导航栏 + 4 张玻璃卡 + Tab Bar（「关于」行刻意非玻璃） | 5 |

设置页第 5 项「关于」刻意做成非玻璃行，用于演示上限；Phase 3 若需更多卡片，应分组折叠或改用系统 `List` 的 glass 分组样式。

## 4. iOS 18 / iOS 26 双版本行为对照表

| 界面/组件 | iOS 18（基线） | iOS 26（增强） |
|---|---|---|
| 底部 Tab Bar | 系统默认 Tab Bar（半透明材质） | `.tabBarMinimizeBehavior(.automatic)`：浮动玻璃胶囊，滚动时最小化，内容从玻璃下穿过（系统自动渲染） |
| 顶部导航栏 | `NavigationStack` 系统半透明 chrome | 系统自动 Liquid Glass chrome（不设 `UIDesignRequiresCompatibility`，新 App 不退回旧外观） |
| 玻璃面板 `GlassPanel` | `.ultraThinMaterial`/`.thinMaterial` + `glassStroke` 描边 | `.glassEffect(.regular/.clear.tint(...)[.interactive()], in: .rect(cornerRadius:))` |
| 聊天输入栏 | 整体 Material 胶囊 + `.bordered`/`.borderedProminent` 按钮 | `GlassEffectContainer(spacing:10)` 合并 3 玻璃元素（加号/输入胶囊/发送），`.buttonStyle(.glass)` + 橙色 tint 发送钮 |
| 消息气泡 / 记忆条目 / 状态区 | 不用玻璃（高对比半透明色） | 同左（双版本一致） |
| 降低透明度 | 玻璃面板退为 `#0B1020 @ 97%` 实色 | 退为 `.regularMaterial`；输入栏玻璃按钮退为 `.bordered` |
| 增强对比度 | 描边加强（18%→34%）、光斑更实、暗角加深 | 同左 |
| 减弱动态效果 | 视差系数归零（背景静止） | 同左；系统玻璃动画自动遵循 |
| 粗体文字 | 描边 1→1.5pt | 同左 |
| Dynamic Type | `.body` 起（≥17pt）自适应缩放，玻璃容器高度随内容 | 同左 |

## 5. 可访问性实现方式

| 系统设置 | 响应位置 | 行为 |
|---|---|---|
| 降低透明度 `accessibilityReduceTransparency` | `GlassPanel`、`GlassInputBar`、`AmbientBackground` | 玻璃退为实色/系统材质；光斑与立绘淡出，保留纯色渐变 |
| 增强对比度 `colorSchemeContrast == .increased` | `GlassPanel`（描边）、`AmbientBackground`（光斑/暗角）、角色头部条 | 描边与光斑加强 |
| 减弱动态效果 `accessibilityReduceMotion` | `AmbientBackground.parallaxFactor` | 视差归零；本 Demo 无自定义玻璃动画，系统转场自动改为淡入 |
| 粗体文字 `legibilityWeight == .bold` | `GlassPanel` | 描边线宽 1.5pt |
| Dynamic Type `dynamicTypeSize` | 全部文本使用语义字体（`.body` 起）；设置页显示当前档位 | 玻璃容器高度自适应，无固定高度裁剪 |

## 6. 附录 C 玻璃验收清单逐条标注

| 附录 C 条目 | 状态 | 本 Demo 实现方式 / 未实现原因 |
|---|---|---|
| Tab Bar 在 iOS 26 上浮动/最小化，滚动时内容从玻璃下穿过 | ✅ 实现（结构） | `.tabBarMinimizeBehavior(.automatic)` 条件修饰符（`TabBarMinimizeModifier`）；**视觉待 runtime 复查**（本机无模拟器 runtime） |
| 导航栏标题、返回按钮为系统玻璃；长按返回有历史栈 | ⚠️ 部分 | 系统 chrome 自动玻璃（iOS 26）；长按返回历史栈是 `NavigationStack` 系统行为，Demo 无二级页面未覆盖，Phase 3 路由验证 |
| 聊天输入栏玻璃不遮挡文字；键盘弹起/收起无跳变 | ✅ 实现（结构） | 玻璃只做背景层（`Capsule().glassEffect(...)`），TextField 文字层 `.foregroundStyle(.primary)`；`.ignoresSafeArea(.keyboard)` + `safeAreaInset`；**键盘无跳变需真机/模拟器实测** |
| 一屏玻璃元素 ≤ 5 个；相邻元素合并无重叠阴影 | ✅ 实现 | 见 §3 计数；输入栏 3 元素经 `GlassEffectContainer(spacing:10)` 合并（无重叠阴影）；**融合视觉效果待 runtime 复查** |
| 深色/浅色模式对比度 ≥ 4.5:1；降低透明度模式下可读 | ⚠️ 部分 | Demo 以深色为主（`preferredColorScheme(.dark)`），深色下文字 `.primary`(白) + 玻璃深底对比达标；降低透明度显式降级已实现；**浅色模式 token 未调校**（Phase 3 跟随系统外观时补齐，见 handoff） |
| 60fps/120fps 滚动无掉帧 | ⛔ 未验证 | 无模拟器 runtime；结构上玻璃仅固定 chrome（列表行零玻璃、零逐行 `.blur()`），理论开销低；**需 Phase 3 Instruments 实测** |
| 玻璃动画 ≤ 300ms；Reduce Motion 下改为淡入 | ✅ 实现（结构） | Demo 无自定义玻璃动画；视差为滚动驱动（Reduce Motion 归零）；系统玻璃转场自动遵循 Reduce Motion；Phase 3 若加 `.glassEffectID` 融合动画，必须 ≤300ms + Reduce Motion 淡入 |
| 弹窗/Sheet 使用系统玻璃；没有「玻璃叠玻璃」 | ✅ 原则落实 | Demo 无自定义弹窗（全部走系统 Alert/Sheet 即自动玻璃）；「玻璃叠玻璃」通过 §1.2 原则 + 12pt 间距规避 |
| 游戏/长文/表格区域不使用玻璃 | ✅ 实现 | 消息气泡、记忆条目、可访问性状态区均为非玻璃高对比色块 |
