# 人设文档 · 写作规范

> 本文件是所有角色人设文档的统一标准。写作前必读，输出必须严格遵循本结构与口吻。

## 一、总原则

1. **忠于游戏原文**。`档案文案`、`他人评价`、`合作备注` 一律**引用原始文本**，不得改写、不得编造官方台词。
2. **解读而非创作**。`人设解读` 允许基于原文推断，但必须能追溯到素材（背景、职业、行为描述、他人评价）。素材没写的，宁可留白，不要编。
3. **克制、观察式的档案口吻**。参考游戏内「详细情报」的语气：像一名冷静的档案员在给同事写备注——平实、点到为止，偶尔一句冷幽默，不煽情、不堆形容词。
4. **为「联系人替换」服务**。读者要拿它去配置聊天软件里的联系人，所以「联系人适配」必须**具体到能直接复制粘贴使用**，不能写空话。

## 二、文件命名

`人设档案/{三位序号}_{中文名}.md`，序号与头像文件前缀一致。例：`人设档案/037_安比.md`。

## 四、各部分写作要求

### 1. 标题与引言
- 标题用「中文名 · 英文名」。
- 引言必须来自 `arch.quote`（档案1）。原文已有「」则不再重复加引号。

### 2. 表格信息
- 缺失字段填「未公开」，不要留空。
- 生日用原文格式（如 `2月20日`）。

### 3. 官方档案
- `档案文案` = `arch.bio` 原文，保留换行。
- `arch.evals` 有两种形态：
  - **新版**（`title` 以「 开头）：`- **{说话人}**：{台词}`，说话人取 `speaker_raw`。
  - **旧版**（`tag` 有值）：`- **{tag}**：{desc}`。
- 若评价人本身就是档案机构/匿名来源（如「一张被揉烂的诊单」），照抄即可，不要强行改成人名。

### 4. 人设解读
- **性格内核**：先给一句话定性（可加粗），再展开。写"他为什么这样"，而不是罗列形容词。
- **行为与语言习惯**：要能指导别人模仿他说话。写清：句子长短、语气词、是否用敬语、爱不爱开玩笑、如何称呼他人。
- **背景与处境**：只用素材里的事实（`detail`、`coop`、阵营设定），拒绝脑补剧情。

### 5. 人际关系
- **只写有依据的关系**：`relations.evaluators` 里出现的人、`relations.mentions` 里提及的人、`relations.faction_mates` 同阵营成员。
- 同阵营默认关系写「同阵营同僚」，除非素材另有说明（师徒、上下级、旧识、竞争等）。
- 依据栏写清来源：引一句原文，或写「同属{阵营}」「档案评价人」。
- 表格 3-8 行即可，不要为了凑数硬拉关系。

### 6. 联系人适配（重点）
| 项目 | 要求 |
| --- | --- |
| 备注名 | 你会在通讯录里存的名字，可带敬称/外号，如「安比」「洛威尔长官」 |
| 个性签名 | 一句话，用该角色的口吻，不超过 20 字 |
| 分组标签 | 阵营或社交圈，如「狡兔屋」 |
| 对你的称呼 | 该角色会怎么叫你，如「绳匠」「店长」「新人」 |
| 开场白示例 | **2 条**，用该角色语气写的招呼语，各 15-30 字，用 `；` 分隔 |
| 典型回复 | **2 条**，回复一件日常小事时的语气示例，用 `；` 分隔 |
| 口头禅 / 关键词 | 3-5 个，用 `·` 分隔 |
| 雷区 / 注意 | 1-2 条，写这个角色**不会**说的话、不会做的事，防止 OOC |

## 五、语言风格红线

- 不要用「她是一个……的人」这种作文腔开头。
- 不要用「综上所述」「总而言之」「值得一提的是」。
- 不要给角色加原文没有的设定（恋爱关系、亲属关系、隐藏身份一律不许编）。
- 不要在正文里写「根据资料显示」这类元叙述，直接陈述。
- 中文标点，引用原文时保留原文标点。

## 六、字数

全文 700–1100 字（不含表格符号）。素材特别少的角色（仅有档案、无详细情报）写 600 字左右即可，不要注水。
